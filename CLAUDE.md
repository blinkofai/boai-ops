# Blink of AI Ops

Internal ops system + client delivery portal for Blink of AI, a creative studio making videos, statics and carousels (mostly for AMCs such as HDFC). The full spec is in `docs/SPEC.md`. Read it before starting a phase.

## Key facts
- The unit of work is the **asset**. Adapts and translations are child assets (`parent_asset_id`) with their own `billable` flag.
- Retainers (HDFC TTP ₹45k/week, Weekend Bytes ₹64k/week) are billed per week **delivered**, using `retainer_weeks`.
- Team: founders (Sandeep, the owner), account managers (Padma, Tejita), 4 editors. Roles: `founder`, `account_manager`, `editor`.
- Domains: `ops.blinkofai.io` (team), `deliver.blinkofai.io` (clients).

## Conventions
- The schema lives in `supabase/migrations/` only. Never change tables in the Supabase dashboard; add a new migration instead.
- Editors read assets through the `editor_assets` view and change status only through `editor_set_status()`. Never expose `price`, `billing` or `invoice_id` to editors.
- Portal routes check the client id on the server. Never trust a client id sent from the browser.
- Asset codes and file names are generated by code (see SPEC §5), never typed by users.
- Claude API calls live in `apps/web/lib/ai/` and return structured output validated with zod.
- Secrets go in `.env.local` / platform secrets, never in the repo.
